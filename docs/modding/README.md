# Modding EQOA Enhanced

EQOA Enhanced runs native Lua mods through the `eqoa` API (`eqoa/1`). Start here.

| Page | Read it for |
|---|---|
| [GETTING-STARTED.md](GETTING-STARTED.md) | The first mod, step by step, and the common patterns |
| [template/](template/) | A starter folder (`mod.json` + `main.lua`) to copy |
| [EXAMPLES.md](EXAMPLES.md) | What each bundled mod shows and which API areas it uses |
| [EQOA-API-SPEC.md](EQOA-API-SPEC.md) | The reference, as built: every function, record, event, error, and the rules for permissions, windows and keys |
| [SUPPORT-TABLE.md](SUPPORT-TABLE.md) | Every name with its status, printed by the client itself (`eqoa mod-api`); `eqoa-1-surface.json` is the same list for programs |
| [VERSIONING.md](VERSIONING.md) | What `eqoa/1` promises, and how to test for features |
| [AGENT-GUIDE.md](AGENT-GUIDE.md) | One page for an AI agent building a mod from a brief |

These pages describe the API as the client is built. The support table is generated by the client and
a test keeps it, the reference and the examples in step with the code. If a page and the running client
ever disagree, the client's own answer wins: ask it with `eqoa.capabilities.get(path)`.

`eqoa/1` is a stable candidate from Enhanced 0.7.0: the guard is on and we do not expect breaking changes.
The final freeze comes when the API is offered upstream, after upstream has had its say; from then on it
only grows ([VERSIONING.md](VERSIONING.md)). Names that no shipped mod uses yet are marked provisional
([PROVISIONAL.md](PROVISIONAL.md)): they may still be corrected after the freeze, with a release-notes entry.
Mods written for FrontiersForge keep running through a
compatibility layer that is not part of that promise.

## HIGH

1. **The chat and command grants have different meanings across entry points** — verified-by-reading. The Forge adapter classifies the final line at `addons/chat.rs:439`. The typed and batch chat paths validate text under the declared action kind, then both kinds enter the same native command parser (`addons/action_broker.rs:3202`, `:3529`, `:4437`, `ext/play.rs:1902`). A player who enables a mod labelled for chat alone can have it perform command actions. Submitting a native chat editor also reaches the parser under the input-text grant (`ext/play.rs:3180`, `crates/eqoa/src/play.rs:8443`). This is also a specification conflict. The builder says slash lines need the command grant, while `docs/modding/EQOA-API-SPEC.md:638` expressly allows slash text in chat. Settle the effective permission at the point of dispatch and make the spec, labels and all entry points agree.

2. **An enabled package can gain Forge acting permissions across a rescan** — verified-by-reading. Native manifests always set the API marker, even if they omit the capabilities list. The legacy package and loose-script discovery paths mark imports structurally, without authenticating their origin (`addons/discovery.rs:449`, `:501`, `:829`, `:930`). The exception and the Forge disclosure both follow that marker (`addons/native.rs:325`, `addons/runtime.rs:881`). Fresh legacy imports default off. For an already-enabled package, a change of package type can retain the old enabled intent by ID and start the newly classified VM automatically (`addons/manager.rs:918`, `:972`, `:305`). The player's earlier choice for a read-only package can thus activate chat, commands and weapon swapping before they see the new disclosure. Bind the enable decision to the effective grants and package type when these expand. Ordinary unchanged Forge imports can keep their compatibility.

3. **Waypoint placement skips the game's world and ground checks** — verified-by-reading. A native click obtains a loaded map and its world, then checks the ground extent for a free point (`crates/eqoa/src/map/mod.rs:595`, `:665`). Lua accepts an arbitrary signed world ID and tests float finiteness *before* narrowing to `f32` (`addons/map_views.rs:182`, `:219`, `:227`). Dispatch checks world entry and the Map setting, then calls the storage setter directly (`ext/play.rs:1395`, `:1981`, `ext/map_api.rs:40`). A stale world ID, unavailable calibration or point outside the map can produce a completed request and a saved, unreachable pin. A finite Lua number can narrow to infinity and replace a valid pin with an entry the settings reader discards on restart (`crates/eqoa/src/settings.rs:273`). Validate the final coordinates against the addressed world's native extent at dispatch. Define which loaded or browsed worlds qualify and how an unavailable map is reported. The current tests cover NaN, an overlong label, map-off and out-of-world calls.

4. **Coordinate equality can delete a player's pin or leave a disabled mod's pin behind** — verified-by-reading. The map stores a pin per world (`crates/eqoa/src/map/mod.rs:1191`), while `addons/map_waypoint.rs:19` stores a single owner for every world and VM. Placing a pin in a second world discards the first ownership record. Disabling the mod then leaves the first persisted pin behind. A player who clears and re-pins the same quest marker can instead lose their own pin. Ownership compares only position, and an absent pin skips the comparison in `ext/map_api.rs:62`. The normal disable path does run: `addons/manager.rs:735` → `addons/native_events.rs:803` → `addons/map_waypoint.rs:79` → next game step at `ext/play.rs:844`. That last drain runs **after** broker dispatch, so it can also erase another mod's new pin at the same spot. Track ownership per world and distinguish successive placements. Exercise disable through the manager, including a player's identical replacement and two worlds.

## MEDIUM

1. **The window switch misses batches that use a merchant or bank claim through conversation** — verified-by-reading. The stop loop visits every VM, but its match depends on the batch's precomputed window flags (`addons/action_broker.rs:779`, `:885`). A talk step is accepted at `:3305` and can arm a merchant or bank opening at `ext/play.rs:1711`. A batch containing conversation and a later unrelated action, without a required window or item transaction, has neither flag. Switching back to game windows releases its claim while the batch remains eligible to advance. Record the claim the batch actually uses, including a target resolved at dispatch.

2. **The Bag Viewer can undercount a stopped sale or pickup** — verified-by-reading. Stopping takes the active batch and publishes its last confirmed count immediately. A later server result has no active batch to update (`addons/action_broker.rs:495`, `:556`, `:871`). Bag Viewer displays that number and clears its batch ID (`bundled-mods/eqoa_bag_viewer/modules/bags.lua:882`). A first sale already on the wire can succeed after the UI reports zero sold. The inventory can subsequently update correctly while the final message stays wrong. Also cancel staged, unsent work: a staged native transaction has separate state that the normal send hook can consume while a native merchant window remains open (`ext/play.rs:963`, `:1061`). The switch fixture at `ext/items_tests.rs:4284` starts after dispatch and never supplies a late success reply. Stop future steps, discard unsent staged work, and distinguish confirmed from pending or unknown outcomes in the terminal result.

3. **Two takeover decisions conflict with the reviewed design** — verified-by-reading. `addons/native_r6a.rs:413` classifies the kind before reading scope. Inventory with helper scope, including its default, gets `unsupported`. Design lines 71 and 103–105 require `invalid_argument` for helper scope on views. It is full replacement of a future view that merits `unsupported`. Separately, the design keeps HUD operations under HUD tokens (line 76) but explicitly includes `hud.target` in *manifest disclosure* (line 88). `addons/discovery.rs:72` now rejects that entire example manifest. Reconcile the declaration vocabulary and error precedence before authors depend on either. The owner explicitly selected settling the scope rules before freeze (design line 358).

4. **The replacement label can promise a capability the mod lacks** — verified-by-reading. `addons/runtime.rs:864` selects the affirmative label from the window kind alone. A valid manifest can name bank in `replaces` and omit the takeover grant. The player sees “Replaces game windows: Bank” even though the gate at `addons/native_r6a.rs:398` refuses every claim. Derive effective replacement labels from both the declaration and grant, or reject an inconsistent manifest with a diagnostic.

5. **Supported typed chat can report completion for a discarded line** — verified-by-reading, inherited and relevant to the gate comparison. `addons/action_broker.rs:3211` permits up to 255 bytes. The native parser silently returns at 128 UTF-16 units (`crates/eqoa/src/play.rs:6385`), after which `ext/play.rs:1910` reports completion. A 128-character ASCII guild announcement can disappear while its author sees success. The same typed binding accepts only text and ignores the documented channel argument (`addons/action_broker.rs:4436`, spec line 638), so a shorter announcement can go to the current channel. Match the native limit and implement or explicitly settle channel selection before freezing this supported method.

The existing defaults migration preserves them in turn (`ext/settings.rs:68`). The upstream options serializer and file format are untouched. Add a native-store round trip with the migration marker and another existing line.
